# Как работает кристалл

Разбор `Assets/Scripts/World/Crystal.cs` и `NetworkCrystal.cs`. Номера соответствуют текущим строкам файлов.

Короткая цепочка воздействия:

`Crystal.Update → Illuminate → ILightSensitive.ReceiveLight`

У игрока `ReceiveLight` восстанавливает рассудок. У врага вызывает `ActorHealth.TakeDamage` с магическим типом урона.

Короткая цепочка повреждения кристалла:

`Goblin.StartThrust → ActorHealth.TakeDamage → HealthChanged → NetworkActorVitals.Publish → NetworkVariable → NetworkActorVitals.Receive → Changed → NetworkCrystal.Apply`

Здоровье хранит `ActorHealth`. `Crystal` управляет светом и воздействием на окружающих. `NetworkActorVitals` передаёт текущее здоровье клиентам. `NetworkCrystal` получает его, применяет состояние кристалла и предоставляет данные для подсказки.

## Crystal.cs

| Строка | Код | Что происходит |
|---|---|---|
| 1 | `using System.Collections.Generic;` | Подключает коллекции `List` и `HashSet`. |
| 2 | `using Unity.Netcode;` | Даёт доступ к `NetworkManager`, через который проверяется сервер. |
| 3 | `using UnityEngine;` | Подключает основные классы Unity. |
| 4 | `using UnityEngine.Rendering.Universal;` | Подключает `Light2D`. |
| 6 | `[RequireComponent(typeof(Light2D))]` | Когда добавляем `Crystal`, Unity также добавляет свет, если его ещё нет. |
| 7 | `public sealed class Crystal : MonoBehaviour` | Обычный компонент Unity. `sealed` запрещает наследование от него. Он есть на сервере и клиентах; обычный класс не означает «только клиент». |
| 9 | `[SerializeField, Min(0.1f)] private float _radius = 6f;` | Радиус воздействия. Поле закрыто для других классов, но видно в инспекторе. `Min` ограничивает ввод в инспекторе. |
| 10 | `[SerializeField, Min(0f)] private float _power = 5f;` | Сила за секунду: при текущих настройках 5 рассудка игроку или 5 базового магического урона врагу. |
| 11 | `[SerializeField, Min(0.05f)] private float _tickInterval = 0.2f;` | Пауза между поисками целей. Сейчас поиск выполняется примерно пять раз в секунду. |
| 12 | `[SerializeField] private LayerMask _targetMask = ~0;` | Слои, на которых искать коллайдеры. `~0` включает все биты, то есть все слои. |
| 14 | `private float _elapsed;` | Время, накопленное с прошлого воздействия. |
| 15 | `private readonly List<Collider2D> _colliders = new();` | Сюда физика записывает найденные коллайдеры. Список используется повторно. `readonly` запрещает заменить саму ссылку, но не менять содержимое списка. |
| 16 | `private readonly HashSet<ILightSensitive> _targets = new();` | Уникальные цели текущего поиска. Несколько коллайдеров одного персонажа не должны умножать воздействие. |
| 17 | `private readonly HashSet<ILightSensitive> _previousTargets = new();` | Цели прошлого поиска. Сравнение двух наборов позволяет увидеть вход и выход из света. |
| 19 | `private void Awake()` | Unity вызывает при создании компонента. |
| 21 | `UpdateLight();` | Настраивает радиус светильника по радиусу воздействия. |
| 24 | `private void OnValidate()` | Unity вызывает в редакторе при загрузке или изменении данных компонента. |
| 26 | `UpdateLight();` | Обновляет свет после правок в инспекторе. |
| 29 | `private void OnDisable()` | Unity вызывает при отключении компонента или объекта. |
| 31 | `_elapsed = 0f;` | Забываем накопленное время, чтобы после включения не выдать накопленный урон. |
| 32 | `ClearTargets();` | Сообщаем целям, что этот источник больше их не освещает. Без этого у игрока мог бы остаться лишний источник в счётчике. |
| 35 | `public void SetDestroyed(bool destroyed)` | Получает состояние разрушения от сетевой прослойки. |
| 37 | `GetComponent<Light2D>().enabled = !destroyed;` | При `destroyed == true` выключает свет. При `false` включает его. |
| 38 | `enabled = !destroyed;` | Аналогично выключает или включает сам `Crystal`. Отключение вызовет `OnDisable` и освободит цели. Коллайдер остаётся доступен для наведения на разрушенный кристалл. |
| 41 | `private void Update()` | Unity вызывает каждый кадр, пока компонент включён. |
| 43 | `if (NetworkManager.Singleton == null || !NetworkManager.Singleton.IsServer)` | Если сети ещё нет или эта копия игры не сервер, воздействовать на персонажей нельзя. `||` означает «или». |
| 45 | `_elapsed = 0f;` | Сбрасываем время вне серверной игры. |
| 46 | `ClearTargets();` | Убираем прежние регистрации света, например после остановки хоста. |
| 47 | `return;` | На этой копии игры заканчиваем обработку текущего кадра. |
| 50 | `_elapsed += Time.deltaTime;` | Добавляем длительность прошедшего кадра к накопленному времени. |
| 51 | `if (_elapsed < _tickInterval)` | Проверяем, прошло ли достаточно времени для следующего воздействия. |
| 52 | `return;` | Если ещё рано, ждём следующий кадр. Поиск коллайдеров пока не запускается. |
| 54 | `float amount = _power * _elapsed;` | Считаем воздействие за реально прошедшее время. Например, `5 * 0.2 = 1`. Если кадр задержался и прошло 0.23 секунды, получится 1.15. Это базовый урон до сопротивления врага. |
| 55 | `_elapsed = 0f;` | Начинаем отсчёт до следующего воздействия. |
| 56 | `Illuminate(amount);` | Передаём вычисленное количество в обработку целей. |
| 59 | `private void Illuminate(float amount)` | Находит тех, кто освещён сейчас, применяет воздействие и отмечает вход/выход. |
| 61 | `ContactFilter2D filter = new ContactFilter2D();` | Создаёт настройки поиска в 2D-физике. Это структура, отдельный объект Unity не создаётся. |
| 62 | `filter.SetLayerMask(_targetMask);` | Ограничивает поиск выбранными слоями. |
| 63 | `filter.useTriggers = true;` | Включает в результаты триггерные коллайдеры. |
| 64 | `Physics2D.OverlapCircle(transform.position, _radius, filter, _colliders);` | Заполняет список коллайдерами, пересекающими круг вокруг кристалла. Учитывается пересечение коллайдера с кругом, а не только положение корня персонажа. |
| 65 | `_targets.Clear();` | Очищает набор текущих целей. Набор прошлого поиска пока сохраняется. |
| 67 | `foreach (Collider2D collider in _colliders)` | По очереди рассматривает каждый найденный коллайдер. |
| 69 | `ILightSensitive target = collider.GetComponentInParent<ILightSensitive>();` | Ищет обработчик света на объекте коллайдера или выше по иерархии. Поэтому дочерний хитбокс тоже приведёт к компоненту персонажа. |
| 70 | `if (target == null || !_targets.Add(target))` | Пропускаем объект без интерфейса. Также пропускаем уже добавленную цель: `HashSet.Add` возвращает `false`, если она там уже есть. |
| 71 | `continue;` | Переходим к следующему коллайдеру, не применяя воздействие повторно. |
| 72 | `if (!_previousTargets.Contains(target))` | Проверяем, не появилась ли цель в свете впервые относительно прошлого поиска. |
| 73 | `target.EnterLight();` | Сообщаем о входе. У игрока счётчик источников увеличивается на один. Это происходит один раз за вход, а не на каждом воздействии. |
| 74 | `target.ReceiveLight(amount);` | Применяем воздействие. Игрок восстанавливает рассудок, враг получает урон. Кристалл не выбирает поведение по типу персонажа: его определяет реализация интерфейса. |
| 77 | `foreach (ILightSensitive target in _previousTargets)` | Теперь смотрим на тех, кто был освещён раньше. |
| 79 | `if (!_targets.Contains(target) && target is Component component && component != null)` | Если цели уже нет в текущем круге, проверяем, что её Unity-компонент ещё существует. Проверка через `Component` нужна, потому что интерфейсная ссылка может сохраниться после уничтожения объекта Unity. |
| 80 | `target.ExitLight();` | Сообщаем о выходе. У игрока счётчик уменьшается на один. Второй кристалл при этом продолжает учитываться. |
| 82 | `_previousTargets.Clear();` | Удаляем старое содержимое набора прошлого поиска. |
| 83 | `_previousTargets.UnionWith(_targets);` | Записываем в него все текущие цели. На следующем воздействии именно этот набор станет «прошлым». |
| 86 | `private void ClearTargets()` | Полностью освобождает цели, когда кристалл больше не должен работать. |
| 88 | `foreach (ILightSensitive target in _previousTargets)` | Перебирает зарегистрированные у этого кристалла цели. |
| 90 | `if (target is Component component && component != null)` | Проверяет, что цель не была уничтожена. |
| 91 | `target.ExitLight();` | Снимает вклад именно этого источника света. |
| 93 | `_previousTargets.Clear();` | Очищает регистрации прошлого поиска. Повторный вызов уже не уменьшит счётчики ещё раз. |
| 94 | `_targets.Clear();` | Очищает текущий набор. |
| 97 | `private void UpdateLight()` | Настраивает светильник; поиск целей здесь не выполняется. |
| 99 | `Light2D light = GetComponent<Light2D>();` | Получает компонент света с того же объекта. |
| 100 | `light.lightType = Light2D.LightType.Point;` | Выбирает точечный источник. У него круговое освещение при углах 360 градусов в префабе. |
| 101 | `light.pointLightOuterRadius = _radius;` | Устанавливает внешний радиус света равным радиусу воздействия. |
| 102 | `light.pointLightInnerRadius = _radius * 0.75f;` | Первые 75% радиуса составляют внутреннюю область, затем свет плавно затухает. Воздействие на персонажа при этом одинаковое во всём радиусе. |
| 105 | `private void OnDrawGizmosSelected()` | Unity вызывает для отрисовки подсказки в редакторе, когда объект выбран. |
| 107 | `Gizmos.color = Color.cyan;` | Выбирает голубой цвет редакторского контура. |
| 108 | `Gizmos.DrawWireSphere(transform.position, _radius);` | Рисует контур радиуса. Коллайдер или дополнительный свет этот вызов не создаёт. |

## NetworkCrystal.cs

Публикация здоровья теперь общая: `NetworkActorVitals`. В `NetworkCrystal` собственной сетевой переменной больше нет.

| Строка | Код | Что происходит |
|---|---|---|
| 1–2 | `using Unity.Netcode; using UnityEngine;` | Подключает NGO и Unity. |
| 4 | `[RequireComponent(...)]` | Требует сетевой объект, общий `NetworkActorVitals` и компонент отображения. |
| 5 | `NetworkBehaviour, ITooltipSource` | Реагирует на сетевой спавн и предоставляет данные общей подсказке. |
| 7 | `private ActorHealth _health;` | Локальное здоровье, используемое до сетевого спавна. |
| 8 | `private NetworkActorVitals _vitals;` | Источник синхронизированного текущего и максимального здоровья. |
| 9 | `private Crystal _crystal;` | Компонент света и воздействия. |
| 10 | `private CrystalVisuals _visuals;` | Компонент отображения повреждений. |
| 12 | `public Vector2 HealthState => ...` | После спавна берёт текущие и максимальные ХП из `State.x` и `State.y`. До спавна берёт их из локального `ActorHealth`. |
| 13 | `TooltipTitle => "Кристалл"` | Название для подсказки. |

| 15 | `TooltipDelay => 1.5f` | Для появления подсказки требуется 1,5 секунды непрерывного наведения. |

| 19 | `_health = GetComponent<ActorHealth>();` | Запоминает компонент здоровья. |
| 20 | `_vitals = GetComponent<NetworkActorVitals>();` | Запоминает общий сетевой компонент здоровья. |
| 21 | `_crystal = GetComponent<Crystal>();` | Запоминает компонент воздействия. |
| 22 | `_visuals = GetComponent<CrystalVisuals>();` | Запоминает компонент отображения повреждений. |
| 25 | `OnNetworkSpawn()` | NGO вызывает при появлении объекта в сетевой игре. |
| 27 | `_vitals.Changed += Apply;` | Подписывается на уже синхронизированные жизненные показатели. |
| 28 | `Apply(_vitals.State);` | Сразу применяет текущее состояние, включая позднее подключение. |
| 31 | `OnNetworkDespawn()` | NGO вызывает при уходе объекта из сетевой игры. |
| 33 | `_vitals.Changed -= Apply;` | Убирает подписку. |
| 34 | `_crystal.enabled = false;` | Прекращает воздействие. `OnDisable` кристалла освобождает освещённые цели. |
| 37 | `Apply(Vector4 state)` | Получает состояние: x — ХП, y — максимум ХП, z — рассудок, w — максимум рассудка. |
| 39 | `_visuals.SetHealth(state.x, state.y);` | Передаёт ХП для выбора видимых трещин. |
| 40 | `_crystal.SetDestroyed(state.x <= 0f);` | При нуле ХП выключает свет и воздействие. |

`NetworkActorStats` передаёт характеристики (`MaxHealth`, урон, сопротивления и т. п.), но не текущие ХП. `NetworkActorVitals` передаёт текущие ресурсы. Рассудок в нём теперь необязателен: у кристалла и скелета компонента `ActorSanity` нет, соответствующие числа равны нулю.

Трещины кристалла появляются по абсолютным порогам: 450, 400, 300, 200, 100 и 50 ХП. При 499 ХП трещин нет. При лечении лишние трещины скрываются.

## Как это связано с рассудком

`EnterLight()` увеличивает счётчик источников в `ActorSanity`, `ExitLight()` уменьшает его. Пока счётчик больше нуля, `ProcessDarkness` ничего не отнимает. Когда он равен нулю, вызывается `DrainSanity(скорость * время)`.

`NetworkActorVitals.Update` вызывает `ProcessDarkness` только для заспавненного объекта на сервере. Событие `SanityChanged` публикует новое значение в уже существующую сетевую переменную жизненных показателей.

Сам кристалл обнаруживает вход и выход при очередном поиске, сейчас раз в 0,2 секунды. Обычный свет игрока не реализует воздействие кристалла и в этот счётчик не входит.
